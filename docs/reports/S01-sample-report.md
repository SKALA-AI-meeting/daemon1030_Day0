## 5. 최종 제출 문서

### 문제 정의·확인한 요구

원문 이용 현황과 대조했다. 신규 가입자 기준 완료율은 240/1,000=24%, 초대 사용자 중 완료율은 240/300=80%로 분모가 다르다. 초대 진입점 개선은 탐색·실험할 가설이며 원인으로 확정하지 않는다. 원문은 최근 4주 표본이며 다른 기간으로 일반화하지 않는다. 초대 방법 문의 18/40은 문의 구성 비율이다.

### 대안 비교·선택 근거

초대 진입점 추가: 2인일, 기존 기능의 발견 경로를 짧게 만드는 안. 초대 단계 관련 문의와 연결되지만 완료율 개선 효과는 미검증이다. 팝업 개선: 3인일, 사용 순서를 설명하지만 초대 기능의 위치를 직접 바꾸지는 않는다. 첫 작업 템플릿: 4인일, 작업 작성 부담을 줄일 가능성이 있으나 현재 가용량 안에서 측정·검증 여유가 줄어든다. 이번에는 초대 진입점 추가를 우선 제안한다. 선택 근거는 문의·이용 흐름과의 관련성 및 개발 제약이며, 다른 안이 효과 없다고 판단한 것은 아니다.

### 최종 개선안·실행 범위

변경 후 제안: 시작 화면에 기존 초대 기능으로 이동하는 진입점을 추가한다(2인일). 분석 이벤트 정비는 1인일 견적이며, 합계 3인일과 나머지 1인일의 확인 여유를 둔다. 분석 작업과 조합할 때 공통 검증 1인일이 추가되는지 담당 확인 전에는 최종 견적을 확정하지 않는다. 추가된다면 총 4인일이며, 다른 의존성이 발견되면 측정 범위도 재협의한다. 첫 작업 템플릿 4인일과 팝업 개선 3인일은 이번 범위에서 제외한다. 출시 주기는 2주를 유지한다.

### 역할·일정·검증 계획

지원자: 문제 정의·대안·최종안·검증 계획 정리. 김도윤: 개발 담당과 추가 검증 비용·의존성 확인, 참고 초안 수정. 개발 담당: 기존 초대 기능 진입점 추가와 분석 이벤트 작업의 최종 견적·구현 가능성 확인. 이후 2주 개발 주기에 맞춰 세부 일정을 협의한다. 확인할 지표는 신규 가입자 기준 7일 이내 완료율, 초대 도달·수행 흐름이다. 출시 전후 사용자 구성이 다르면 단순 전후 비교만으로 개선 효과를 확정하지 않는다. 미확정: 분석 정비와 조합할 때 공통 검증 비용 적용 여부, 구현 순서와 담당별 구체 마감.

## 7. 생성 과정과 현재 자동화 범위

1. 시나리오의 고정 사건은 기존 S01-v1 설정에서 읽었습니다.
2. 가상 지원자·직원·어시스턴트 대화와 문서 변경을 설명용으로 작성했습니다.
3. 기록에 순서·가상 경과 시간·원문·출처 ID를 부여했습니다.
4. 선택 역량과 실제 시나리오 관찰 규칙을 포함한 스냅샷을 만들었습니다.
5. 현재 `services/report_worker/observations/report.py`의 `build_report`를 호출했습니다.
6. 자동 결과의 모든 근거 원문이 입력 기록과 일치하는지 확인했습니다.
7. 사람이 읽을 수 있도록 결과를 배열하고, 자동 출력과 구분한 수동 검토 메모를 덧붙였습니다.

현재 워커는 정해진 상황 이후 시간 범위의 메시지·문서 변경을 연결합니다. ‘질문이 적절하다’, ‘협업을 잘한다’, ‘AI 결과를 검증했다’ 같은 의미 판정이나 이 문서의 수동 요약을 자동 생성하지 않습니다. 최종 리포트의 문장 수준을 이 예시처럼 확장하려면 근거 검증과 함께 별도로 설계·구현해야 합니다.
