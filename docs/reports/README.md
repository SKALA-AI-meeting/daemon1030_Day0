# 리포트 예시와 웹 조회

## 웹에서 확인할 리포트

- 프로젝트: 샘플 응시 · 신규 기능 개선안 리포트
- 지원자 별칭: 가상 지원자 A · 예시 답변
- 기업 계정: `ui.company@example.test`
- URL: http://127.0.0.1:5173/projects/9d6bf5c6-14b6-4886-bd09-ab8c5a1b4188
- 기업으로 로그인한 뒤 해당 지원자의 **리포트 보기**를 누릅니다.
- 세션 ID: `07799f8c-7a4f-43cc-90d4-ad8d22919f80`

작성한 가상 답변·문서 변경을 개발 전용 재생 명령으로 저장하고, 실제 제출 API → 최종 스냅샷·Outbox → RabbitMQ → report-worker → 리포트 API → 웹 화면 경로를 확인했습니다. 직원과 118분간 실제 대화한 응시가 아니라 가상 시간의 합성 기록입니다. 개인 테스트 계정의 기존 응시는 수정하지 않고 별도 프로젝트·초대를 만들었습니다.

자동 생성된 결과는 역량 5개, 근거 7개, 활동 기록 35개입니다. 근거에는 DB의 실제 사건 ID가 연결됩니다. 기존 Markdown의 수동 검토 메모는 웹 자동 리포트에 포함하지 않았습니다.

## 파일 예시와의 차이

- `S01-sample-records.json`: 직접 작성한 가상 원본 입력. `demo-` ID는 작성용 참조입니다.
- `S01-sample-report.json`: 위 입력을 함수에 직접 넣어 생성했던 결과입니다. DB에서 내려받은 파일은 아닙니다.
- `S01-sample-report.md`: 자동 연결 결과와 수동 검토 메모를 구분한 설명 문서입니다.
- 웹의 리포트: 실제 DB 사건 ID로 참조를 다시 연결하고 제출·큐·워커로 새롭게 생성한 결과입니다. 동의·시작·데모 출처 기록이 포함되어 파일 예시보다 활동 수가 많습니다.

## 재현

로컬 개발 스택을 실행한 뒤 기존 기업·개인 테스트 계정의 비밀번호를 `DAYZERO_DEMO_PASSWORD` 환경 변수로 제공하고 아래 명령을 실행합니다. 비밀번호를 출력하지 않습니다. 동일 프로젝트 요청 ID를 재사용하고 제출된 예시는 덮어쓰지 않습니다.

```sh
uv run --env-file .env python -m services.gateway.demo_report
```

새 응시의 실제 사용자 답변이 이미 있으면 재생을 거절합니다. 일반 운영 모드에서는 명령을 사용할 수 없으며 웹에 시계 조작·기록 가져오기 API를 추가하지 않았습니다.

## 결과물 검토·역량별 AI 평가 v2

- 프로젝트: 샘플 응시 · 신규 기능 개선안 AI 최종 평가
- 웹: http://localhost:5173/projects/966895cc-7d32-4a27-9c12-3e5b64f9cd07
- 세션: `bfb9c63c-6373-4b1e-92fc-a99131f4c03b`
- 실제 API 저장본: [S01-v2-web-report.json](S01-v2-web-report.json)

가상 답변을 별도 S01-v2 프로젝트에서 제출하고 실제 gpt-4o-mini로 결과물 6개 기준과 역량 5개를 검토했습니다. 업무 원본·최종 스냅샷은 유지하며, 개발 전용 `--refresh-ai`로 이 샘플의 AI 의견만 재생성할 수 있습니다. 인용은 서버가 등록된 원문 구절 번호로 직접 연결합니다. 인용·스키마 검증 통과는 의미 해석의 정확성을 보장하지 않으며 담당자가 판단과 원문을 함께 검토해야 합니다.

```sh
uv run --env-file .env python -m services.gateway.demo_report --scenario-version S01-v2
```

기존 `S01-sample-report.md`의 수동 검토 메모와 달리 v2 웹의 의견은 실제 모델 출력입니다. API 저장본에도 그 출처를 구분합니다.
