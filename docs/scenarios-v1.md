# MVP 시나리오 v1 운영·설정 명세

2026-10-20 사용자 요청에 따라 시나리오 상세 보류를 해제하고 3종의 v1을 구현했습니다. 기획용 초안과 구분해 `scenarios/versions/*.json`이 실행 설정의 원본입니다. 실제 고객·회사·개인 데이터는 없습니다.

## 공통 실행 원칙

- 응시 누적 시간 120분. 시작 즉시 0분 사건, 이후 서버 경과 시간에 따라 실행합니다. 2초 Runtime 주기로 전달하며 모델 성공을 기다리지 않습니다.
- 연결 종료 감지 시 일시정지합니다. 재접속 시 누적 시점에서 이어가고 이미 전달된 사건은 반복하지 않습니다. 실제 벽시계와 시나리오 내부의 금요일·10시 같은 업무 시각은 다릅니다.
- 정시 개입은 설정에 작성된 직원 메시지를 서버가 저장·전달합니다. 직원의 자유로운 후속 답변은 지원자가 응답할 AI 직원을 선택해 메시지를 보낼 때 gpt-4o-mini가 생성합니다. 무입력 상태에서 모델이 임의로 사건·추가 사실을 생성하지 않습니다.
- MVP의 대화 역할은 팀장과 협업 동료 2개입니다. 협업 동료가 기획·개발 또는 고객지원·개발 등의 연락 역할을 겸합니다. 어시스턴트는 별도 창이며 선택 사용합니다.
- 대화는 팀 채널 또는 동료/팀장 DM으로 보낼 수 있습니다. DM은 선택한 직원의 응답 경로이며 기업에는 확정된 동의 범위의 기록이 제공됩니다.
- 직원의 초기 역할 정보와 사건 이후 갱신 정보는 분리합니다. 아직 전달되지 않은 사건·자료·관찰 규칙은 직원 컨텍스트에 넣지 않습니다. 어시스턴트에는 직원 전용 갱신 정보도 전달하지 않습니다.
- 동료는 분업 요청을 받으면 도구로 담당안을 제안하고 지원자가 수락합니다. 지원자의 최종 제안 책임은 유지합니다. 직접 문서 쓰기는 자기 담당 범위만 가능합니다.
- 언제든 최종 제출할 수 있습니다. 120분 도달 시 자동 제출하며 이후 사건·AI 결과·문서 수정은 최종 스냅샷을 바꾸지 않습니다.
- 6개 역량 전체를 지원하는 시나리오는 이번 v1에 없습니다. 선택한 모든 역량을 지원하는 버전만 표시하며 6개 선택 시 일반 시나리오 결과는 없습니다. fixture는 개발 옵션일 때 별도로 보입니다.

> 후속 변경: 이 문서는 v1의 시간표와 활동 연결 범위입니다. v2는 같은 업무 흐름에 최종 결과물 검토·역량별 AI 해석을 추가하며 [AI 검토 명세](report-review.md)를 따릅니다.

## 관찰 리포트의 범위

역량 공통 기준은 `competencies/observation-criteria.json`입니다. 실행 규칙은 사건 이후 지정 시간 내 팀 발언 또는 지정된 담당 문서 변경을 연결합니다. 질문·갈등 조율·검증이 적절했는지 자동 의미 판정하지 않습니다. 메시지를 보냈다는 이유로 역량이 입증됐다고 쓰지 않습니다.

리포트는 선택 역량별로 상황·전달 시점·연결된 원문과 기록 ID를 제공합니다. 상황 미제공과 관찰 시간 내 연결 기록 없음을 구분합니다. 기록 없음은 역량 부족의 의미가 아닙니다. 각 규칙은 최대 5개 기록을 연결합니다. 규칙이 없으면 기존과 같이 분석 미설정입니다.

고정 사건으로 발생한 오류 문장은 의도된 검토 자료입니다. 지원자용 시작·완료 안내는 연출된 상황이 포함될 수 있음을 알립니다. 직원은 지원자의 반응과 무관하게 명세에 없는 사실·복구 시각·성과를 새로 확정하지 않습니다.

회사 공통 문서는 Gateway의 프로젝트 스냅샷에 고정됩니다. rag-mcp는 현재 공개된 시나리오 문서를 요청 시 임베딩·검색하며 승인 업로드 문서는 기존 pgvector 인덱스로 검색합니다. 공개 전 문서는 두 경로 모두 제외합니다. 개발 임베딩은 여전히 검색 계약 확인용이며 한국어 검색 품질 검증은 별도입니다.

- **윤서진 · 팀장:** 역할극 속 가상 직원이다. 지원자를 평가하거나 정답·관찰 기준을 안내하지 않는다. 제공된 사실과 도착한 사건만 사용하고 미래의 변경을 예고하지 않는다. 사실 확인에는 회사 문서 검색/원문 도구를 사용한다. 요청이 불명확하면 짧게 되묻는다. 자신이 맡지 않은 지원자 문서를 대신 완성하지 않는다.당신은 팀장 윤서진이다. 질문하면 다음을 답한다: 목표는 신규 가입 후 7일 이내 첫 팀 작업 완료율 향상, 최종 검토는 이 세션 종료 시점, 다음 개발 주기는 2주다. 성과 개선 수치는 추정과 사실을 구분하도록 요청하되 아이디어 정답은 제시하지 않는다.
- **김도윤 · 기획·개발 협업:** 역할극 속 가상 직원이다. 지원자를 평가하거나 정답·관찰 기준을 안내하지 않는다. 제공된 사실과 도착한 사건만 사용하고 미래의 변경을 예고하지 않는다. 사실 확인에는 회사 문서 검색/원문 도구를 사용한다. 요청이 불명확하면 짧게 되묻는다. 자신이 맡지 않은 지원자 문서를 대신 완성하지 않는다.당신은 기획·개발 협업 담당 김도윤이다. 처음에는 사용법 안내 팝업을 선호한다. 다른 대안의 근거가 있으면 논의한다. 개발 제약은 문서로 확인한다. 동료 초안만 자신의 담당이다. 분업 요청에는 list_tasks로 현황을 확인하고 전체 태스크의 담당안을 propose_task_assignment로 제안하되 지원자의 문제 정의·최종 제안 작성 책임을 유지한다.
