# docs — 아키텍처·개발·검증 문서 범위

기준: [루트 설계](../AGENT.md). 루트는 전체 설계, 폴더별 AGENT.md는 구현 책임, 이곳은 읽기 쉬운 개발·운영·시연 설명을 담당한다.

## 작성할 문서

- 아키텍처: Vue·Gateway·Agent·MCP 2개·워커·DB·큐, 데이터 소유권·신뢰 경계·공개 범위·실패 흐름.
- 개발 환경: 필요한 런타임·환경 변수·의존성·마이그레이션·서비스 기동·테스트·중지·재시작. 실제 확인한 명령만 성공 예시로 기록.
- 기업·개인 흐름: 역량 3~6개·지원 시나리오·프로젝트·초대·개인 응시 완료·기업 개인별 리포트.
- 서비스 연동: API·MCP·공개 사건·큐 계약의 위치, 서버별 실행 방법·내부 포트·권한.
- 복구·승인: Graph 체크포인트 재개, 문서 승인/거절, Outbox·큐 재시도·DLQ, 원본/스냅샷·분석 상태.
- 평가표: 기본 100점·가산점 10점의 구현 대상·검증 결과·시연 순서·미구현 사항과 실행 증거 위치.
- 결정 기록: 선택 근거·대안·미정 항목과 상태. 제품 합의와 구현 제안을 구분한다.

## 단일 기준과 연결

- 최신 사용자 합의·루트 설계를 따른다. PRD에 남은 이전 단일 시나리오·다른 프론트 기술·초대만으로 입장하는 흐름을 현행으로 복제하지 않는다.
- API·도구·사건 필드는 contracts로 링크하고 표를 복사해 별도 진실을 만들지 않는다.
- 역량 정의는 competencies, 시나리오 이름·상태는 scenarios, 환경 명령은 infra·실제 설정과 연결한다.
- 규칙 미설정·분석 미설정, 관찰 없음·AI 미사용·실행 실패를 명확히 설명한다.
- 문서 양식·태스크·자료·사건은 주입 설정이며 서비스 공통 고정 사항처럼 설명하지 않는다.

## 맡지 않는 범위

시나리오 3종의 구체 과제·대사·자료·지원 역량 매핑, 임의의 제품 정책 확정, 실행 코드·DB 변경, 실제 개인정보·키·토큰 수록, 검증되지 않은 상용화·심리측정·규제 준수 주장.

## 완료 기준

현재 구현·설계·보류 상태가 구분되고 링크·실행 명령·환경 이름이 실제 파일과 일치한다. 평가 증거는 실제 실행 ID·버전과 연결하며 계획을 통과 결과처럼 쓰지 않는다. 루트 설계와 책임 경계에 모순이 없고, 새 개발자가 담당 폴더·연결 지점·검증 방법을 찾을 수 있다.
