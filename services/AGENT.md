## 공통 구현 원칙

- Python 서버를 독립 실행 단위로 두고 공용 요청·응답·사건은 [contracts](../contracts/AGENT.md)로 정의한다.
- 다른 서버의 구현 모듈·ORM을 직접 import해 서비스를 우회하지 않는다. 공용 폴더에 업무 로직을 복제하지 않는다.
- 외부 브라우저는 Gateway에만 연결한다. Agent·MCP·DB·큐는 내부 서비스다.
- 사용자 인증과 서비스 인증을 구분한다. 기업·세션·역할은 검증된 실행 컨텍스트에서 결정한다.
- 서버 간 자격은 수신 서비스별 audience·scope·만료를 검사한다. 브라우저 자격을 그대로 통과시키지 않는다.
- Gateway가 세션 시간·원본 업무 상태의 기준이다. 모델·Graph 체크포인트·웹 캐시가 이를 덮어쓰지 않는다.
- 변경 요청의 멱등 키·revision, 입력 사건 순서, 최종 제출 스냅샷을 연결한다.
- 세션·초대·리포트 상태를 분리하고 `not_configured`와 실행 실패를 구분한다.
- 모델은 `gpt-4o-mini`만 사용한다. 사내 자료·사건·역할 지침은 설정으로 주입한다.
- 로그에는 trace/run/command ID를 연결하되 키·초대 토큰·불필요한 개인정보를 남기지 않는다.

## 공통 범위 밖

- 시나리오 상세 데이터의 소유권은 scenarios에 있다. 2026-10-20 사용자 승인으로 3종 v1을 주입하며 공통 서비스에 내용을 하드코딩하지 않는다.
- 미정인 최대 재개 기한·보관 기한을 임의의 제품 정책으로 확정하는 것.
- 공유 DB를 이유로 서비스별 데이터 소유권을 무시하는 것.

## 통합 완료 기준

- 기업 프로젝트 생성 → 개인 초대 수락·응시·제출 → 큐 작업 → 기업 리포트 조회가 계약으로 연결된다.
- 두 MCP 서버의 실제 도구 조회·호출·변경·오류와 Graph 저장·재개 증거가 남는다.
- 모델·Agent·워커 실패가 저장·필수 사건·자동 제출을 불필요하게 멈추지 않는다.
- [migrations](../migrations/AGENT.md)·[infra](../infra/AGENT.md)·[tests](../tests/AGENT.md)와 동일한 테이블 소유권·서비스 이름·실행 설정을 사용한다.
