# rag-mcp — 공개 문서 검색·승인 인덱싱 구현 범위

기준: [루트 설계](../../AGENT.md) 6.1·6.2·6.4·6.5장, [서비스 공통](../AGENT.md).

## 역할과 기술

Python·FastMCP, Streamable HTTP `/mcp`, 기본 내부 포트 9102. PostgreSQL·pgvector에 검색용 청크·벡터를 저장한다. 임베딩 모델·차원은 구현 전 계약·DB와 함께 고정하며 현재 문서에서 새 선택을 확정하지 않는다.

## 구현할 도구

| 도구 | 기능 | 허용 범위 |
|---|---|---|
| `search_company_documents` | 질의·top_k로 허용 문서 검색 | 동료·팀장·어시스턴트, 읽기 scope |
| `get_company_document` | 허용 문서 원문·버전 조회 | 직접 ID 조회도 동일 공개·권한 검사 |
| `stage_company_document` | Gateway 원문 버전을 검색 제외 준비 상태로 등록 | 관리 Graph 전용 |
| `index_approved_document` | 승인 대상 해시를 검증해 청크·벡터 생성 | 관리 Graph 전용, 승인 필수 |

## 검색 책임

- 기업·시나리오 고정 버전·승인·공개 조건을 검색 후보 단계에서 제한한다. 검색 후 모델이 비공개 내용을 숨기도록 맡기지 않는다.
- Gateway의 인증된 내부 API로 허용 버전·공개 상태를 확인한다. 검색과 원문 조회·캐시에 같은 기준을 적용한다.
- 반환에는 문서·버전·청크 ID, 제목, 근거 본문과 인용 정보를 포함한다. 응답 크기·top_k 상한을 둔다.
- 캐시 키에 기업·시나리오 버전·공개 문서 집합을 포함한다. 공개 상태 변경·버전 교체 시 오염을 막는다.
- 빈 문서·검색 결과 없음은 정상 빈 결과로 반환한다. 문서가 없는데 내용을 만들어내지 않는다.
- 숨겨진 사건·관찰 규칙·동료 비공개 지시는 검색 코퍼스로 수집하지 않는다.

## 인덱싱 책임

- 원문·기업 소유권·관리자 승인 레코드의 주인은 Gateway다. 여기서는 준비 문서·청크·벡터·인덱스 상태를 관리한다.
- 준비 도구는 등록된 원문 버전만 읽고 내용 해시·변경 요약을 반환한다. 준비 문서는 검색되지 않는다.
- 승인 도구는 Gateway가 확인한 관리자 결정·기업·해시를 검증한다. Agent가 넘긴 approved 값만으로 실행하지 않는다.
- 내용 변경·거절·만료/잘못된 자격이면 인덱싱을 차단한다. 같은 command_id의 재시도는 중복 인덱스를 만들지 않는다.
- 실패 시 기존 발행 인덱스를 유지한다. 새 버전의 성공은 진행 중 세션의 자료를 교체하지 않는다.
- 읽기와 관리 쓰기 scope·DB 권한을 나눈다. 문서 승인 interrupt·재개 Graph는 Agent가 소유한다.

## 연결·범위 밖

Agent가 유일한 모델용 MCP Client이며 입력·결과는 [contracts](../../contracts/AGENT.md)를 따른다. 사용자·사내 문서 원문·승인 API는 Gateway가 담당한다. LLM 최종 답변·업무 태스크 변경·역량 분석·실제 사내 문서 집필은 여기서 구현하지 않는다.

## 완료 기준

- Agent에서 검색·원문 조회·관리 변경 도구가 실제 호출된다.
- 타 기업·비공개·미승인·다른 고정 버전 자료가 검색·직접 조회·캐시로 새지 않는다.
- 준비 → 승인/거절 → 인덱싱 → 검색 흐름을 fixture 문서로 재현한다.
- 인덱싱 실패·해시 불일치·재시도·타임아웃과 기존 인덱스 보존을 검증한다.
