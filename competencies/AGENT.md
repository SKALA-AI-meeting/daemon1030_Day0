# competencies — 역량 정의·버전 관리 범위

기준: [루트 설계](../AGENT.md) 1.3·7장. 이 폴더는 역량 데이터의 기준이며 분석 실행 엔진이 아니다.

## 고정 역량 목록

| ID | 이름 | 관찰하려는 행동의 범위 |
|---|---|---|
| C01 | 의사소통·요구 파악 | 모호한 요구 확인, 핵심 정리·전달, 이해 확인 |
| C02 | 협업·갈등 조율 | 역할·의견 차이 조율, 도움 주고받기 |
| C03 | 책임 이행·일정 관리 | 진행·지연·실수 공유, 담당 업무·일정 관리 |
| C04 | 문제 해결·우선순위 판단 | 원인·제약 파악, 대안·실행 순서 제안 |
| C05 | 변화 대응·피드백 수용 | 변경·피드백 확인, 계획·결과물 반영 |
| C06 | 비판적 검토·AI 활용 | 근거 대조, AI 위임·맥락 전달·결과 검토 |

## 구현할 범위

- 계약 형식에 맞춰 역량 코드·이름·정의·버전·상태를 데이터로 관리한다.
- 묶인 역량의 세부 행동을 식별할 구조를 두되 결과를 임의 점수로 환산하지 않는다.
- 향후 확정된 관찰 규칙의 ID·버전·적용 조건·필요 근거·한계·중립 문구 메타데이터를 관리한다.
- 해당 규칙이 정의됐는지와 실제 세션에서 관찰되지 않았는지를 구분할 수 있게 한다.
- 정의·규칙 수정은 새 버전으로 발행한다. 기존 프로젝트의 참조를 바꾸지 않는다.
- Gateway의 역량 목록·프로젝트 검증, 웹 표시, 워커 결과 항목이 같은 ID·정의를 참조하게 한다.

## 경계와 제한

- 서비스용 행동 관찰 영역이며 검증된 인적성 검사의 공식 척도나 성격 진단이라고 주장하지 않는다.
- 기업이 3~6개를 고르는 UI는 web, 최종 선택 검증은 Gateway가 담당한다.
- 2026-10-20 사용자 승인에 따라 공통 관찰 기준 v1과 시나리오별 관찰 기회 매핑을 작성한다. 자동 의미 판정·점수화로 확대하지 않는다.
- 규칙 구조는 contracts, 향후 시나리오별 관찰 기회 연결은 scenarios, 실제 지표 계산 코드는 report_worker가 소유한다.
- AI 미사용·관련 행동 없음으로 부정적 수준을 만들지 않는다. 수정 사용과 검증을 동일시하지 않는다.
- 경제적 보상·외향성 등 합의되지 않은 새 선택지·가중치·컷오프·성격 점수는 추가하지 않는다.

## 완료 기준

- C01~C06이 중복 없이 정확히 정의되고 각 소비자가 같은 버전을 사용한다.
- 메타데이터 형식 검증·버전 참조·알 수 없는 ID 거절이 가능하다.
- 실제 연결 가능한 규칙과 의미 해석 한계를 구분하고, 미정 규칙 때문에 가상의 평가를 생성하지 않는다.
