# contracts — 서비스 간 계약 구현 범위

기준: [루트 설계](../AGENT.md) 1.3·4·6·7·9장.

## 역할

서비스 간 요청·응답·사건·도구·시나리오 설정의 형식을 단일 기준으로 정의한다. Python 서버와 Vue가 같은 의미·버전·오류·상태를 사용하도록 한다. 업무 실행 로직과 DB 모델을 공유하는 폴더가 아니다.

## 작성할 계약

- `api/`: 기업·개인 인증, 역량, 시나리오 조회, 프로젝트·초대·개인 평가·동의·시작·업무·제출·리포트, 내부 API·문서 승인.
- `mcp/`: 두 서버의 도구 이름·설명·inputSchema·outputSchema, 역할별 scope, 성공·업무 실패·프로토콜 오류 구분.
- `events/`: 저장 사건·WebSocket 공개 사건·Agent 입력/상태·리포트 큐 작업. 소비자와 생산자를 명시한다.
- `scenario/`: 시나리오 버전·상태, 과제·역할 지침·문서 참조·양식·태스크·사건·공개 조건·지원 역량·규칙의 구조. 내용은 비워 둔다.
- 관찰·리포트: 규칙·근거 참조·원문 범위·관찰 기회·수집 사실·역량별 결과·생성 상태 형식.

## 반드시 정의할 의미

- 역량 ID와 시나리오 ID의 값은 각각 competencies·scenarios가 소유한다. 이곳은 타입·검증 형식만 소유한다.
- 기업 ID·세션·역할·scope는 서버 실행 컨텍스트이며 모델이 자유 입력해 권한을 얻는 필드가 아니다.
- 선택 역량 3~6개·중복 불가·지원 집합 전체 포함을 API 조건으로 명시하고 Gateway에서 최종 검사한다.
- revision·command_id·생성 요청 ID·trace/run ID·멱등 키와 재시도 시 재사용 규칙.
- 사건의 seq·occurred_at·elapsed_ms·payload_version, 저장 완료·임시 delta·내부 전용 필드의 차이.
- 초대·응시·리포트 상태를 분리하고 not_configured를 포함한다. submitted는 리포트 ready와 다르다.
- 오류 코드: NOT_FOUND, ACCESS_DENIED, DOCUMENT_NOT_AVAILABLE, SESSION_CLOSED, VERSION_CONFLICT, INVALID_TRANSITION, TIMEOUT, RATE_LIMITED와 입력 검증 오류 형식.
- 입력 크기·필수/선택/null·단위·시간대·ID·버전 형식을 명시한다. 근거 문서에는 문서·버전·청크 ID가 필요하다.
- 계약 변경은 생산자·소비자를 함께 확인한다. 호환되지 않는 변경은 버전을 분리한다.

## 다른 폴더와의 경계

- Gateway: 외부/내부 API·업무 상태. Agent: 실행 입력·State 참조·공개 처리 상태.
- MCP 서버: 실제 도구 등록·인가·처리. 워커: 큐 소비·규칙 실행·리포트 검증.
- scenarios/schemas가 필요하면 이곳의 설정 계약을 참조하거나 생성한 결과만 둔다. 수동으로 이중 정의하지 않는다.
- migrations는 저장 구조를, 이곳은 전송 형식을 소유한다. 전송 객체를 ORM 엔터티로 공유하지 않는다.

## 범위 밖과 완료 기준

실제 서버·DB 접근·모델 호출·시나리오 대사·기업 업무 로직은 작성하지 않는다. 계약별 정상·오류 예시는 tests/fixtures에서 합성 데이터로 검증한다. 필드 변경 시 소비자 누락, 내부 필드의 웹 노출, 두 MCP 서버의 실제 도구 계약 불일치가 없어야 한다.
