# tests — 계약·서비스 통합·사용자 흐름 검증 범위

기준: [루트 설계](../AGENT.md) 12·13장. 테스트는 실제 구현과 위험에 맞춰 추가하며 현재 존재하지 않는 실행 명령·테스트 통과를 주장하지 않는다.

## 구성

- `unit/`: 선택 역량·상태 전이·가시성·멱등성·인용 검증·규칙 계산 등 핵심 로직.
- `integration/`: Gateway와 DB, Agent와 실제 MCP 서버, RAG 공개/승인, RabbitMQ와 워커, 체크포인트 복구.
- `e2e/`: Vue 기업 프로젝트·초대·개인 응시·제출·기업 리포트 흐름.
- `fixtures/`: 합성 계정·문서·원본 스냅샷, 빈 설정, 최소 임시 사건·매핑·규칙. 예정 시나리오 3종의 상세안을 만들지 않는다.

## 필수 검증

1. 역량 2개·중복·미등록·7개 이상 거절, 3개·6개 허용(지원 발행본 존재 시), 선택 집합 전체 일치, 결과 없음·미발행 제외.
2. 기업·개인 역할, 타 기업 프로젝트·리포트, 다른 개인의 초대·응시 차단. 만료 자격과 계정 귀속 확인.
3. 동의 전 시작 금지, 시작·초대 수락·제출 중복 처리, 종료와 자동 저장·늦은 AI 응답 경합.
4. 사건 실행 선점·중복·재기동·빈 목록, 공개 전 문서의 API·검색·원문·캐시·맥락 유출 방지.
5. 두 MCP 서버의 실제 초기화·tools/list·tools/call·조회·변경, 스키마, 오류·권한·타임아웃·revision 충돌.
6. 어시스턴트의 쓰기 도구·숨겨진 지시 접근 차단. 실제 모델 도구 선택 시연과 단순 MCP 연결 검증을 구분.
7. Graph 분기·반복·호출 한도, 체크포인트 저장·프로세스 재시작·재개 후 중복 변경 방지.
8. 문서 준비·승인 전 비노출, 거절·해시 변경·권한 거절, 승인 후 인덱싱, 실패 시 이전 인덱스 유지.
9. 종료·Outbox 원자성, 작업 중복·워커 재시작, 저장 후 ACK·실패 재시도·DLQ·작업 유실 방지.
10. 선택 역량만 리포트 포함, 근거 인용·시각·세션 일치, 동일 스냅샷/규칙 지표 동일, 관찰 없음·기회 없음·AI 미사용·not_configured 구분.
11. AI 결과 수정 사용을 검증으로 오인하지 않고, 점수·순위·합격 판단·근거 없는 성격 단정이 없는지.

## 실행·환경 경계

- 테스트 DB·큐·저장 경로를 분리하고 운영·개인 데이터를 초기화하지 않는다. 자격은 합성·단기 값으로 사용한다.
- 기본 자동 테스트는 외부 모델 키·유료 호출 없이 결정적으로 실행한다. 모델 제공자는 계약에 맞는 대역을 사용한다.
- 실제 MCP 프로토콜 통합은 도구 실행을 확인한다. LLM이 도구를 선택했다는 증거는 별도 명시적 모델 통합 시연으로 남기고 혼동하지 않는다.
- 가상 시계로 지연을 줄이고 운영 코드와 같은 사건 엔진을 사용한다. 시계 조작은 개발 환경에만 허용한다.
- 연결 종료 일시정지·재접속·언제든 제출은 확정 정책으로 검증한다. 최대 재개 기한·보관 기간은 임의의 테스트로 확정하지 않는다.

## 다른 폴더와의 경계·완료 기준

서비스 담당자는 자기 핵심 동작과 테스트를 함께 변경하고 이곳의 공통 통합·fixture를 재사용한다. 스키마는 contracts, 의미는 competencies, 실제 시나리오는 scenarios가 소유한다. 실행 방법은 docs, 환경은 infra와 맞춘다.

버그 검출·경계·복구 중심으로 검증하고 단순 문서·구현 복사 테스트를 늘리지 않는다. 실패 시 재현 명령·실제 결과·원인을 남기며 테스트를 위해 제품 권한·근거 검증을 약화하지 않는다.
