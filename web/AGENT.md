# web — 기업·개인 프론트엔드 구현 범위

기준: [루트 설계](../AGENT.md) 1·3·9장. 이 문서는 구현할 범위이며 기능 구현 완료를 의미하지 않는다.

## 역할과 기술

Vue 3·Vite·Vue Router로 기업·개인 사용 흐름과 가상 오피스를 구현한다. 모든 업무 요청과 실시간 연결은 Gateway를 이용한다.

## 구현할 기능

- 기업·개인 가입·로그인·로그아웃, 로그인 상태 복원, 역할에 따른 경로·메뉴 분리.
- 기업: 프로젝트 목록 → 생성 → 역량 6개 중 3~6개 선택 → 가능한 시나리오 조회 → 하나 선택 → 생성 → 지원자 초대.
- 선택 부족·중복 제출·시나리오 없음·권한 부족·요청 실패 상태를 표시한다. 조건 미달 시 생성을 막되 최종 검증은 서버가 수행한다.
- 기업: 프로젝트별 지원자 목록, 응시·리포트 상태, 개인별 선택 역량의 근거 리포트. 점수·순위·합격 판단은 표시하지 않는다.
- 개인: 로그인 → 본인 초대·평가 목록 → 안내·동의 → 시작 → 가상 오피스 → 제출·완료 → 디브리핑.
- 오피스: 팀 채널·동료 DM, 자동 저장 과제 문서, 태스크 보드, 공개 사내 문서, 서버 기준 남은 시간.
- 어시스턴트: 별도 창의 요청·응답·인용·처리 상태. 문서 자동 수정 없이 지원자가 내용을 사용한다.
- 사건·대화·태스크·문서 변경을 반영하고 임시 토큰 출력과 저장 완료 메시지를 구분한다.
- 최소 관리자 문서 준비·변경 요약·승인/거절 UI를 제공한다. 확장 문서 관리 화면은 P1이다.
- P1: 브라우저 이어하기 UX, 근거 원문 위치 이동. 준비되지 않은 기능을 동작하는 것처럼 표시하지 않는다.

## 내부 구성 방향

- `router/`: 기업·개인 경로와 접근 검사. 화면 가드는 서버 인가를 대체하지 않는다.
- `api/`: HTTP·실시간 클라이언트, 공통 오류 매핑.
- `stores/`: 인증·프로젝트·응시 상태. 역할 전환·로그아웃 시 이전 데이터 제거.
- `features/`: auth, projects, invitations, assessments, office, assistant, reports.
- `layouts/`, `components/`: 레이아웃·공통 UI. 실제 필요할 때 하위 폴더를 만든다.

## 연결 계약과 경계

- Gateway의 `/auth/*`, `/competencies`, `/scenario-options`, `/projects`, 프로젝트별 초대·지원자 API, `/me/assessments`, 세션·리포트 API를 사용한다.
- 오류·상태·사건 형식은 [contracts](../contracts/AGENT.md)를 따른다. 가시성에 따라 서버가 내보낸 자료만 사용한다.
- 문서 항목·태스크·역할·공개 자료는 설정과 API로 받는다. 특정 회사·고정 항목 수·사건 시각을 코드에 넣지 않는다.
- AI 응답 복사·사용 연결을 기록할 수는 있지만 수정·붙여넣기만으로 검증 행동이라고 표시하지 않는다.
- 관찰 규칙이 없는 개발 실행은 `분석 미설정`으로 표시한다. fixture 기반 가짜 분석 결과를 일반 리포트로 보여주지 않는다.

## 맡지 않는 범위

- 모델·MCP·DB 직접 접근, API 키 보관, 서버 권한 결정, 실제 세션 시계·사건 실행.
- 시나리오 상세 작성, 역량 채점·성격 판정, 어시스턴트의 직접 문서 수정.
- 기업별 통계 대시보드·실시간 공동 편집·기업용 시나리오 편집기.

## 완료 기준

- 기업·개인 전체 경로가 실제 Gateway와 연결되고 역할별 접근과 빈 목록·오류·만료 상태가 처리된다.
- 선택 2개는 진행 불가, 3~6개는 지원 시나리오가 있을 때만 생성 가능하다.
- 서버 응시 완료와 리포트 생성 대기를 분리해 보여준다. 제출 뒤 편집을 차단한다.
- 문서 충돌·저장 실패를 알리고, 실시간 재연결 시 저장된 사건을 순서대로 복원한다.
- 빌드 검증과 핵심 사용자 흐름의 [E2E](../tests/AGENT.md)를 통과한다.
